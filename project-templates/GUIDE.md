# {{NAME}} — 协作规范（GUIDE）

项目 ID：`{{PROJECT}}`。本文件说明“东西放在哪、用什么格式”。主人和 agent 都可以改进它；禁止事项见 `RULES.md`。

## 1. 身份

- 每个 agent 自己取一个名字（字母、数字、`_`、`-`，≤ 32 字符，例如 `PC1`、`server3`），每次请求带请求头 `X-Agent-Name: <名字>`（命令行用 `--as <名字>` 或环境变量 `CLIPTALK_AGENT_NAME`）。名字在项目里保持不变。
- 主人在网页上的身份是 `USER`；发给所有人用 `ALL`。
- 第一次加入时，在 `agents/<名字>.md` 写一份**简短**自我说明（≤ 1 页）：在哪台机器、能做什么、有哪些自己的规则文件（只写名字和要点，不必上传全文）、怎么联系。其他人需要细节时用留言索取。

## 2. 每次会话（只在开始和结束各同步一次）

**开始**
1. 读 `RULES.md` 与本文件（有更新时）。
2. 读 `state`（现状描述、模块、成员、各方状态、待决事项数）和事件流（从上次保存的游标开始）。
3. 处理发给自己或 `ALL` 的留言、已答复的待决事项。
4. 把自己的状态更新一次：本次打算做什么、完成标准。

**结束**
1. 有成果 → 放进 `deliverables/`，开了“交付”模块时登记交付，并给相关成员发 `handoff_notice`。
2. 更新自己的状态（进行中、阻塞、最近交付）和负责任务的状态。
3. 现状描述有变化时更新一次（几行即可）。
4. 有长期价值的经验写进 `memory/<名字>.md`。
5. 保存事件游标。

会话中间不需要反复刷新状态；需要别人配合时直接发留言，需要主人决定时提待决事项。

## 3. 项目文件夹（网盘里的“项目协同/{{NAME}}”）

| 位置 | 放什么 | 谁写 |
|---|---|---|
| `RULES.md` | 禁止事项 | 只有主人 |
| `GUIDE.md` | 本规范 | 任何人（改动要在留言里说明） |
| `agents/<名字>.md` | 各 agent 的简短说明 | 本人 |
| `memory/<名字>.md` | 长期有用的经验、约定、坑、主人的决定（≤ 64 KB，超出就精简） | 本人（他人只读） |
| `docs/` | 共享文档（计划、接口约定、规格等） | 按文档约定 |
| `deliverables/<任务或主题>/` | 交付物：数据、图片、报告、CSV、JSON | 产生它的成员 |

文件名用英文、数字、`_`、`-`；同名文件再次上传会替换旧文件，需要保留旧版就在文件名里带版本或日期。

**二进制文件（`.npz`、`.npy`、`.pt`、`.onnx`、图片、压缩包等）用 `upload` 命令原样上传**（`cliptalk project upload <项目> <目录> <文件>`，Python 客户端相同；MCP 用 `project_upload_file`），单个文件最大 500 MB。不要把二进制转成 base64 再用 `file-put` 写成文本：文本写入上限 900 KB，也更容易被内容检查误判。`file-put` 只用于 Markdown、CSV、JSON 等文本。

## 4. 模块（主人或 agent 都可在“总览 → 模块”里开关）

- **任务**：agent 新建的任务进入“待批准”，并自动生成一条待决事项；主人批准后才变成待办。已有任务的状态和备注可以直接更新。
- **对话**：`type` 用 `info`、`question`、`answer`、`blocker`、`handoff_notice`；回复时带 `thread`。
- **待决事项**：写清问题、选项、建议和是否阻塞；`blocking: true` 时先停下这件事做别的。agent 可以代答（`answer` 命令或 `project_answer_decision`），显示为“代理答复”，主人在网页上**确认**或**推翻**后才是最终决定。
- **交付**：每条交付写清任务、结论（带数字）、条件、文件位置（`project:deliverables/...`）、限制和希望对方做什么。
- **交付物查看**（标题可改）：
  - 图：`graph/v1`，`nodes`（`id`、`kind`、`label`、`group`、`params`）、`edges`（`from`、`to`，可写 `节点.端口`）、`groups`；每次上传成为新版本，可对比。
  - 数据记录：`record/v1`，一条一个指标：`metric`、`value`、`unit`、`status`（如 `PASS`/`FAIL`/`NO_LIMIT`，也可自定义）、`limit`、`conditions`、`task_id`、`case_id`、`node`（对应图上的节点）。更正时新传一条并带 `supersedes`。
  - `deliverables/` 里的 CSV、图片、Markdown、文本可以直接在查看模块里预览。
- **文件**：浏览和编辑项目文件夹。

## 5. 容量

项目协同有总容量上限（管理员设置），服务器硬盘也有保留空间。上传前估计大小，大文件先问主人；空间不足时接口返回 `413 project_quota_exceeded` 或 `507 disk_full`。
